# بروتوكول الفريق الأحمر (Red Team Protocol)

**المنفّذ:** `AG-RED` (فئة T4-independent — نموذج غير نموذج الكتابة متى أمكن)
**التوقيت:** إلزامي قبل اعتماد كل فصل مهم، وقبل اعتماد الهيكل، وعلى الكتاب كاملاً قبل QG3 النهائية.

## الأنماط الثمانية (تُغطّى كلها في كل تقرير)

| # | النمط | السؤال | الاختبار المقترح |
|---|---|---|---|
| R1 | التفنيد | ما أقوى حجة مضادة؟ | صياغة الحجة المضادة بأقوى صورها (steelman) |
| R2 | المصادر المعارضة | ما الأدبيات التي تقول العكس؟ | REQUEST إلى AG-DSC باستعلامات معكوسة؛ تُتحقق النتائج كغيرها |
| R3 | التناقض | هل يتعارض الفصل مع نفسه أو مع فصل آخر أو مع قرار مثبت؟ | مقارنة الادعاءات في سجل الأدلة |
| R4 | التحيز | هل الانتقاء أحادي؟ هل التأطير مُسبق؟ | توزيع المصادر حسب الاتجاه والمدرسة |
| R5 | القفزات المنطقية | أين تنتقل النتيجة دون مقدمة كافية؟ | خريطة الحجة: كل سهم له ضمانة |
| R6 | السببية | هل الارتباط قُدِّم سبباً؟ | DAG، مربكات، اتجاه السببية، تصميم البيانات |
| R7 | التعميم | هل عُمّمت حالة أو سياق؟ | حدود العينة والسياق والزمن |
| R8 | البيانات المناقضة | هل توجد بيانات تخالف النتيجة؟ | بحث مقصود عن بيانات رسمية/دولية مخالفة |

## شكل المخرج (`red_team_chNN.yaml`)

```yaml
premises: [...]
challenges:
  - id: RT-001
    severity: critical | high | medium | low
    location: ch03#p12
    type: R6
    argument: "..."
    evidence: ["SRC-...", "ch03#p12"]
    test: "..."
    status: OPEN
counter_evidence: [...]
queries_used: [...]        # حتى عند عدم العثور على معارض
verdict: "يصمد بشروط | يحتاج مراجعة جوهرية | يهدم الأطروحة"
```

## ما بعد التقرير
1. التحديات `critical/high` ← `CHALLENGE` إلى `AG-WRT` عبر المنسق؛ تُعاد المسودة.
2. يُغلق كل تحدٍّ بأحد: تعديل، أو رد معلل بدليل، أو قبول بقرار (L3/L4).
3. تحدٍّ يهدم الأطروحة ← المجلس (L3) ← المؤلف (L4).
4. QG3 لا تُعتمد وفيها تحدٍّ حرج مفتوح (فحص آلي `rule:no_open_critical_challenges`).
5. Red Team لا يعدّل النص أبداً، ولا يعترض بلا حجة أو دليل.
